My recommendation

Don't recreate any commercial architecture yet.

Instead, create a Commercial Policy Discovery & Reconciliation exercise, exactly like we're doing for the frontend.

The output would answer:

What commercial capabilities already exist?
Which documents define them?
Which database tables already support them?
Which APIs already exist?
Which UI already exists?
What is MAP CLI aware of (probably nothing)?
What belongs to the Platform versus the MAP Product?
What is missing?

I suspect you'll discover that 70–80% of the commercial architecture has already been designed, just scattered across multiple documents. The exercise would consolidate it into a single authoritative commercial architecture rather than rewriting it.


Phase 08.5 — Frontend Architecture & Capability Reconciliation

Purpose:

Establish the authoritative relationship between the frozen frontend, MAP CLI capabilities, and existing Workstream UI policies before Phase 09 implementation.

Step 1 — Inventory Existing Frontend Policies

Review:

01_Prompts/
 ├── Workstream_01_Platform_Foundation

 ├── Workstream_03_Presentation_Engine
 ├── Workstream_05_Frontend
 ├── Workstream_06_Frontend

Do not rewrite them.

Classify each as:

Category	Action
Already implemented in frozen frontend	Restore/reuse
