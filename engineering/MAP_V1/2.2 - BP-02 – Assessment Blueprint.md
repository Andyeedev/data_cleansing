# 1. Purpose

The Assessment Blueprint defines the standard methodology for initiating and conducting a Migration Assurance Platform (MAP) assessment.

Its purpose is to establish a structured, evidence-based approach for evaluating an organization's migration readiness, identifying risks and opportunities, and producing actionable recommendations that guide the migration programme.

The Assessment Blueprint ensures that every engagement follows a consistent process, regardless of industry, technology stack, or cloud provider.

---

# 2. Objectives

The Assessment Blueprint aims to:

* Establish the current state of the organization.
* Define the desired target state.
* Assess business, technical, operational, and governance readiness.
* Identify risks, dependencies, and constraints.
* Validate migration assumptions.
* Produce prioritized recommendations.
* Create a baseline for future assurance activities.
* Provide executive decision support.

---

# 6. Assessment Domains

MAP evaluates ten core domains:

| Domain            | Purpose                                          |
| ----------------- | ------------------------------------------------ |
| Business Strategy | Alignment with business objectives               |
| Governance        | Decision-making and oversight                    |
| Applications      | Portfolio complexity and suitability             |

| Operations        | Operational processes and service management     |

Each domain is assessed independently and then consolidated into an overall readiness profile.

# 11. Assessment Scoring Model

Each domain is scored using a five-level maturity scale:

| Score | Maturity   |
| ----- | ---------- |
| 1     | Initial    |
| 2     | Developing |
| 3     | Defined    |
| 4     | Managed    |
| 5     | Optimized  |

Overall readiness categories:

* **0–20%**: Not Ready
* **21–40%**: Early Readiness
* **41–60%**: Partially Ready
* **61–80%**: Ready with Improvements
* **81–100%**: Fully Ready

# 17. Best Practices

* Interview business leaders before technical teams.
* Validate documentation through workshops.
* Use multiple evidence sources.
* Avoid assumptions without proof.
* Focus on business outcomes rather than technology alone.
* Prioritize recommendations by business value and risk.
* Maintain a clear audit trail.
