# Design Principles

Before we write a single paragraph, I'd like to establish six governing principles.

### Principle 1 – One Source of Truth

There will only ever be one official definition of:

* the company
* the product
* the platform
* the roadmap
* terminology
* customer segments
* commercial strategy

Everything else references this.

---

### Principle 2 – Evidence Before Marketing

Every statement must be one of:

✅ Current Capability

🟡 Planned Capability

🔵 Vision

Nothing in between.

No hype.

No invented functionality.

---

### Principle 3 – Audience Neutral

The Product Canon is **not** written for:

* Microsoft
* Investors
* Banks
* Developers

It is written for **our company**.

Every external document becomes a filtered view of the Canon.

---

### Principle 4 – Business First

The Canon starts with:

Why we exist.

Not

What framework we use.

Technology supports the business—not the other way around.

---

### Principle 5 – Stable Core

This document should still make sense three years from now.

Only a few sections should change regularly:

* Roadmap
* Current Capabilities
* Product Maturity
* Commercial Model

Everything else should remain largely stable.

---

### Principle 6 – Modular

Each section must be independently reusable.

For example:

* Website uses Vision + Value Proposition
* Microsoft uses Vision + Azure Alignment
* Investors use Vision + Market + Commercial Strategy
* Sales uses Problem + Solution + ROI

No rewriting.

# Before we write the first chapter

I want to establish one final rule that I think will significantly improve the quality of everything we produce.

## Canon Acceptance Criteria

Every chapter must satisfy these five questions before it is considered complete:

1. **Is it technically accurate?**
2. **Is it commercially meaningful?**
3. **Is it understandable by a non-technical executive?**
4. **Can it be reused without rewriting?**
5. **Does it remain valid as the product evolves?**

If the answer to any of these is "no," we revise the chapter before moving on.
